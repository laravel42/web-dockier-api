# Auth API

## Endpoints

- `POST /auth/register/start`
- `POST /auth/passwordless/start`
- `POST /auth/passwordless/verify`
- `POST /auth/2fa/setup`
- `POST /auth/2fa/enable`
- `POST /auth/2fa/verify`
- `GET /auth/me`
- `GET /auth/memberships`
- `POST /auth/tenants`
- `POST /auth/tenants/:tenantId/switch`
- `POST /auth/tenants/:tenantId/transfer-ownership`

## Auth model
- Members are added, re-roled and removed through the users API (`/users`), which enforces role hierarchy and owner protection. Removing a member deletes their account only when they belong to no other organization.

- Registration is passwordless: call `POST /auth/register/start`, then verify OTP via `POST /auth/passwordless/verify` with `type=signup`.
- Supabase Auth handles passwordless email OTP/magic-link verification.
- Dockier issues a tenant-scoped API JWT after OTP verification. For an account with 2FA enabled, `POST /auth/passwordless/verify` returns `{ twoFactorRequired: true, challengeToken }` instead (valid 5 minutes); `POST /auth/2fa/verify` with that token and an authenticator code or a one-time recovery code issues the session. Enabling 2FA returns 10 recovery codes once; only their hashes are stored.
- Tenant role is app-managed in `organization_memberships` (`admin` or `member`).
- New self-registered users default to `member` role unless explicitly provisioned as `admin` (for example via admin seeding).
- Authorization does not rely on mutable `user_metadata`.

## Supabase Auth settings

- Enable **Email provider** with OTP/magic-link in Supabase Auth.
- Keep **Enable email signups** turned on, or `POST /auth/register/start` will return a 403.
- Magic links always redirect to the Supabase **Site URL**: the API takes no `redirectTo`, so a link cannot be pointed at another host. Set the Site URL to the frontend.
- `POST /auth/passwordless/verify` is rate-limited per IP and per email (10 attempts per 15 minutes per email, per backend instance).

## Typing conventions

- Input validation uses Zod route schemas.
- Response contracts are explicitly declared per status code.
- Authenticated routes use a typed JWT context (`request.auth`).
