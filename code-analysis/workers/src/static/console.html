Worksheet

Exercise every service

Steps run independently, but they read best in order: the router tells you what exists, the scan API is what your application calls, and the workers are where a scan actually happens. Each step keeps a short transcript, newest first, so you can compare calls.

01

Ask the router what exists

/services returns the registry — every service and the path it answers on. /health probes them all concurrently and returns 503 if any is unreachable, so a green result here means the whole topology is up. Neither needs a token.

GET/services
GET/health
No response yet.
02

Enqueue a scan

Returns as soon as the job is durably queued — not when the scan finishes. Unknown option keys are rejected rather than ignored, so a typo cannot quietly mean enabled. Try one to see the error shape.

POST /sast/scans/…/run
No response yet.
03

Watch it progress

Poll for status, summary, per-engine outcome and live progress. Two fields decide how you present the result: summary.partial means an engine failed, so zero findings may mean nothing looked; and qualityGateStatus stays null on a partial scan, because the engine that died is the one that might have found the error.

GET /sast/scans/…
No response yet.
04

Read the findings

Suppressed findings are marked, never deleted — the LLM filter flags them and they stay queryable. includeSuppressed is how a reviewer audits what was filtered out, and counts.suppressed tells you how much there is to audit even when the list excludes it.

GET /sast/scans/…/findings
No response yet.
05

Reach an individual worker

Each worker answers on /workers/{name} with its own health, metadata and a manual trigger. Trigger enqueues rather than running inline, so a triggered job obeys the same concurrency cap, retries and expiry as any other. Useful for isolating which service is down when aggregate health goes red.

Reference

What the responses mean

Authentication is per-tenant, and the router does not do it

The api service verifies the token itself and scopes every query to its tenantId. A router that authenticated on the services' behalf would become one component whose compromise grants access to every tenant's scans.

A scan belonging to another tenant returns 404, not 403 — confirming that an id exists is itself a disclosure.

A clean scan and a broken one look alike unless you check

status is a closed enum — pending, running, completed, failed — with no room for degraded. Read summary.partial and engineStatus before presenting a result as clean.

Errors carry a code, not just prose

Every failure returns { "message", "code" }. The message names the field when a parameter is at fault, so it can be shown to a user directly rather than mapped.

CodeHTTPWhen you will see it
UNAUTHORIZED401Missing, malformed, expired, or signed with a different secret.
NOT_FOUND404No such scan for your tenant. Also returned for another tenant's scan.
UNKNOWN_SERVICE404The path named a service that does not exist. The message lists the valid ones.
VALIDATION_ERROR422Bad parameter or unknown option key. The message names the field.
UPSTREAM_TIMEOUT504A service did not answer the router in time.
UPSTREAM_UNAVAILABLE503A service is down. Probe it directly in step 05 to confirm which.
AUTH_NOT_CONFIGURED500JWT_SECRET is unset. The API fails closed rather than skipping auth.
INTERNAL_ERROR500Deliberately generic — the underlying message can contain a clone URL with a token.
